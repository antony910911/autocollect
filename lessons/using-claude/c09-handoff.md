# 第 9 章　什麼時候換新對話，交接清單怎麼寫

## 9.1 三個選擇，先分清楚

![圖 9-1　`/clear`、`/compact`、`/rewind` 各做什麼](figures/fc9-1-when-to-switch.png)

| 指令 | 做什麼 | 什麼時候 |
|---|---|---|
| `/clear` | **清空**。全新開始 | **換題目了** |
| `/compact` | **壓縮**。換成摘要，繼續同一題 | 同一題但太長了 |
| `/rewind` | **倒帶**。退回先前某一點 | **走錯路了** |

## 9.2 什麼時候 `/clear`

> **換題目就換對話。**

判斷很簡單：**接下來要做的事，需不需要用到剛才那些檔案和結論？**

- 不需要 → `/clear`
- 需要 → 繼續，或 `/compact`

具體的訊號：

- 剛推完一個東西，要開始做**別的**
- 你發現自己在講「好，那現在換一件事」
- `/context` 顯示對話內容佔了一大半，而**那些都是舊題目的**

**不要捨不得。** 舊對話裡的東西對新題目沒有幫助，只會：佔位子、每一句話都重送（花錢）、還可能讓它把兩件事搞混。

> 想之後找得回來：**先 `/rename 取個名字` 再 `/clear`**，之後用 `/resume` 回去。

## 9.3 什麼時候 `/compact`

**同一題，但太長了。** 例如一個複雜的除錯弄了三小時，還沒結束。

**壓縮的時候要講你要留什麼：**

```text
/compact 專心保留圖的版面問題和已經試過的解法
```

不講的話它自己猜。猜錯了，你剛才試過的十種方法可能被摘掉，接下來它會叫你再試一次。

### 壓縮之後哪些東西會自己回來

這張表很值得記，因為它決定了你要在交接清單裡寫什麼：

| 東西 | 壓縮之後 |
|---|---|
| `CLAUDE.md`（專案根目錄）、自動記憶 | **會自動回來** |
| 技能的名字和說明 | **會重建回來** |
| 計畫模式寫的計畫 | **會自動回來** |
| 它讀過或改過的檔案 | **只會重讀最近改過的五個**。超過 5,000 token 的只留路徑，不留內容 |
| 用過的技能內容 | 會接回來，但**每個最多 5,000 token、全部共用 25,000 token**，超過從最舊的丟 |
| `.claude/rules/` 裡 `paths:` 的規則 | **不會自動回來**，跟對話一起被摘掉 |
| 你們的對話 | **變成一段摘要** |

**所以壓縮之後最容易掉的是**：你們討論出來的結論、試過但失敗的方法、以及第六個以後的檔案。

→ 這三樣，就是交接清單一定要寫的東西。

## 9.4 什麼時候 `/rewind`

**它走錯路了，而且已經改了檔案。**

`/rewind` 可以把**對話和程式碼**一起退回先前某一點。輸入框空的時候連按兩下 `Esc` 也是這個。

這比「叫它把剛才改的改回來」可靠得多——退回去是確定的，叫它改回來是它再猜一次。

`/rewind` 裡還有兩個選項：**從某則訊息開始摘要**、**摘要到某則訊息為止**。想只壓縮一段、保留其他的時候用。

## 9.5 交接清單：範本

換對話之前，叫它寫一份。**不要自己寫**——它比你記得清楚，而且它知道哪些檔案被碰過。

### 叫它寫

```text
我要開新對話繼續這件事。幫我寫一份交接清單，包含：
1. 我們在做什麼、做到哪裡
2. 改過哪些檔案，各自改了什麼
3. **試過但失敗的方法，以及為什麼失敗**
4. 下一步具體要做什麼
5. 有哪些還沒決定的事

寫成 markdown，我要貼到新對話裡。
```

**第 3 點是最重要的。** 沒有它，新對話會興高采烈地再試一次你已經試過的錯誤方法——這是最常見、也最浪費的狀況。

### 清單長這樣

```markdown
## 在做什麼
把 BMB171 PHB 的分析整理成 Folio 教材分區。

## 做到哪裡
- `lessons/bmb171-phb/` 已建立，8 章＋導讀都寫完
- `code/checks.py` 查核過原文數字，全部一致
- 8 張圖都畫完，check_geometry 和 check_layout 都過

## 改過的檔案
- `lessons/bmb171-phb/`（新增，整個資料夾）
- `CLAUDE.md`（加了新分區的說明）

## 試過但失敗的（不要再試）
- 圖的標題本來自己畫在 (40, 46)，**和 `Svg()` 第三個參數畫的標題重疊**。
  標題要交給 `Svg(w, h, "圖 N-M　標題")`，不要自己再畫一次。
- 字型子集**沒有「孤 擠 縱」這三個字**，用了會變 fallback 字體。
  這個環境裝不了新字型（沒網路），只能改用字。

## 下一步
推到 `claude/ammonia-nitrogen-degradation-a0nidi`，確認 Actions 兩個 job 都綠。

## 還沒決定
第 1 章那個碳帳（0.5973 vs 0.4779）要不要也放進導讀。
```

### 然後

1. 把清單貼進一個檔案，或直接複製
2. `/rename bmb171-教材`（之後找得回來）
3. `/clear`
4. 在新對話第一句貼上清單

## 9.6 更省事的做法：寫進檔案

如果這件事會做好幾天，與其每次複製貼上，不如**寫成一個檔案放在專案裡**：

```text
notes/handoff-bmb171.md
```

新對話第一句：

```text
@notes/handoff-bmb171.md 這是上次的進度，接著做下一步
```

一個 `@` 就帶進去了（第 5 章），而且下次還在。

> 做完了記得刪掉或清空，不然它會變成另一份過期的文件在誤導人。

## 本章重點

- **換題目 → `/clear`；同題太長 → `/compact 要留什麼`；走錯路 → `/rewind`。**
- 捨不得清是最常見的浪費。舊對話對新題目沒幫助，只會佔位子、花錢、搞混。
- **壓縮最容易掉的是：結論、試過的失敗方法、第六個以後的檔案。**
- 交接清單**叫它寫**，而且**一定要有「試過但失敗的」**那一段。
- 會做好幾天的事，把清單寫成檔案，用 `@` 帶進新對話。
- `/clear` 之前先 `/rename`。
